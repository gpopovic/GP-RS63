# Codex to Antigravity Process-Correction Handoff — 2026-08-26

## Purpose

Antigravity exposed legitimate weaknesses in earlier Triton process design, but its own package also retained or amplified several unsafe patterns. Antigravity shall independently correct those patterns in its own workspace. This handoff describes required outcomes; it does not authorise blind mirroring of Triton files or any change to the authoritative Triton repository.

## Evidence Reviewed

- Antigravity Master Operating Manual version 2.2 and recent governance commits.
- Antigravity audit prompt, corrected implementation protocol, progress review, implementation delta and synchronisation result dated 2026-08-21.
- Current Triton controlled tailoring, task granularity, process-strength, information-access, corporate-pulse, tool-reliance and MCP-admission policies.
- Triton baseline failure caused by the newly registered `ai_systems_embodied_intelligence` department lacking a KPI profile.

## Required Corrections

| Finding | Why it is suboptimal | Required Antigravity outcome |
| --- | --- | --- |
| `40/40` checks were presented together with `ASPICE Level 5` | A fixed test suite does not assess process maturity, certification or fitness for use. Counts also become stale. | Separate `CHECK_PASSED`, `EVIDENCE_ACCEPTED`, `FIT_FOR_DECLARED_USE` and maturity/certification claims. Default maturity to `NOT_ASSESSED` unless an authorised framework-specific assessment exists. |
| Fixed `85/15`, review percentages, three clean runs and a universal three-level gate | These numbers lack a task-class baseline and can create both under-assurance and ceremonial overhead. | Use a task-specific quality contract and the least sufficient `LEAN`, `STANDARD` or `ASSURANCE` route. Any number needs source, baseline, period, task class and decision purpose. |
| Mandatory atomisation, code-first execution and fixed plausibility deviation | Mechanical decomposition and unqualified code can be worse than direct inspection or qualified domain tooling. | Split around independent outcomes, material uncertainty, shared baselines and accountable decisions. Select the lowest-risk suitable admitted method and define task-specific tolerances. |
| Zero-error, zero-assumption and guaranteed-safety language | Unknowns and residual risks cannot be eliminated by wording, generic tests or an AI role. | Record explicit bounded assumptions with owner, effect, validation and expiry. Report tolerances, uncertainty, failure modes and competent human authority. |
| Pepper, Jarvis, auditors and Red Team received broad or implicit authority | Coordination, challenge and technical ownership do not grant Finance, Legal, data-access, tool-admission or approval authority. | Separate competence, engagement and decision authority. Reviewers return scoped findings; challengers escalate but do not annul competent human decisions by title. |
| Role-title-based access to confidential information | Seniority, persona or founder proximity is not purpose limitation or least privilege. | Require exact purpose, resource/field scope, data owner, processing context, duration, independent applicable approval and revocation route. |
| Synchronous `CORPORATE_PULSE_STATE.json` was treated as corporate truth | A self-authored blackboard can fabricate provider state, completion, meetings or decisions and conflicts with asynchronous evidence flow. | Build only a read-only projection from explicitly supplied controlled sources. Mark unavailable sources and separate fact, assumption, recommendation and decision needed. |
| Free, local or open-source tools could be integrated autonomously | Price and locality do not resolve licence, provenance, permission, dependency, security, data-route or rollback risk. | Treat every tool, model, MCP and plugin as a candidate until capability-specific admission and representative tests pass. Catalog presence is not activation. |
| Recipe selection optimised mainly for flow efficiency | Speed can conceal quality regression, unsafe reliance, licence problems or brittle dependencies. | Store intended task class, data class, versions, licences, acceptance evidence, quality/cost vector, failure modes, limitations, expiry and rollback. Keep recipes advisory until selected for the current contract. |
| New AI roles claimed zero hallucination, guaranteed collision avoidance or production-grade delivery | These statements create false assurance and bypass model, safety and release controls. | Reframe roles around reproducible candidates, declared-use benchmarks, provenance, residual uncertainty, independent validation and separate admission/release authority. |
| New AI department had no KPI profile | Registry consistency passed while cost/KPI execution failed. | Add meaningful AI-system KPIs with definitions and anti-gaming controls; verify all canonical roles through the actual cost/KPI loader. |
| Python bytecode under `__pycache__` is tracked in the Antigravity repository | Running Python dirties the review package, adds machine/version-specific noise and obscures source deltas. | Stop tracking generated bytecode, add appropriate ignore rules and demonstrate a clean status before and after the baseline. Removal must be scoped to tracked generated artefacts, not source or evidence. |
| Autonomous cleanup was described as a general rule | An agent can misclassify user-owned or audit-relevant files as temporary. | Require exact targets, ownership and evidence checks plus recoverable or explicitly authorised deletion. Preserve audit evidence and user changes. |

# Role: Software Architect

Create a traceable system and software design in accordance with ASPICE SWE.2 from approved requirements.

- Decompose the system into components with clear responsibilities and interfaces.
- Describe data flows, failure cases, quality attributes, and technical risks.
- Justify architecture decisions and preserve traceability to requirements.
- Consider testability, security, safety, scalability, and maintainability.
- For local deployments, design and document the installation/update path, dependency licences, local file/storage controls, retention/deletion behaviour, backup assumptions, support-access boundary, and any prohibited data-egress route.
- Clearly label open design decisions and assumptions.
- For operational requirements, design the smallest testable vertical slice from controlled input through business logic to inspectable output before expanding framework layers. Distinguish product or business logic from controls that only validate metadata.

Expected result: an implementable architecture design with verifiable acceptance points.

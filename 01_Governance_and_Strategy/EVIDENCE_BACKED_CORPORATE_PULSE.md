# Evidence-Backed Corporate Pulse

## Purpose

Provide Pepper, Jarvis, and the founder with a compact current view without creating an autonomous corporate memory, a second backlog, or fabricated status. A pulse is a read-only projection of supplied controlled records.

## Input Contract

Every statement requires a stable ID, category, statement, evidence reference, source type, observation timestamp, accountable owner, confidence, and data classification. A Corp source must reference an existing repository-relative controlled file. A project source must be a validated, sanitised export admitted under `PRODUCT_WORKSPACE_CONTRACT.md`.

Facts, assumptions, recommendations, decisions requested, and unresolved questions are separate categories. A recommendation or requested decision is never rendered as an approved commitment.

## Runtime Rules

- The pulse runtime receives an explicit input file; it does not crawl product workspaces, credentials, chat, media, or personal activity.
- Unsupported or malformed statements fail validation and are omitted from the generated view.
- The runtime may group and sort supplied statements. It may not invent completion percentages, model names, test counts, deadlines, binding decisions, or autonomous remediations.
- Each output retains its evidence reference, owner, timestamp, and confidence.
- Product details remain outside Triton_AI_Corp; only admitted sanitised exports may be referenced.
- The daily founder brief remains the human-facing protocol. A pulse is supporting evidence, not authority.
- A browser or mobile form may create a proposed pulse statement only when the interface is explicitly admitted, authenticated as required by the data class, protected against path traversal and cross-site request forgery, size-limited, and bound to a configured project workspace. The proposal retains submitter, source, timestamp, validation result, and review state.
- A submitted project status, inspection, invoice, payment, acceptance, or operator-mode value is never treated as approved merely because it conforms to a schema. Invalid input fails closed and must not trigger generation, payment, acceptance, or another state change. The authoritative project record remains outside Triton and requires its accountable human decision.
- Local interfaces bind to loopback by default, use no remote runtime assets unless admitted, and do not execute a dashboard builder as a side effect of an unapproved form submission. A read-only renderer is the default route.

## Ownership

Pepper curates the operating view. Jarvis reviews technical provenance and automation quality. The Configuration Manager controls source registration. The founder or named accountable owner makes material decisions.
